# 环祥货期跟踪

深圳环祥电子货期工程师用的静态页面。用来看捷德、奔强两家外发 PCB 厂的 WIP 走到哪一道工序，以及伯仁订单和 WIP 对得上哪一单。

页面部署在 GitHub Pages：<https://link5268.github.io/wip-tracker/>

订单和 WIP 只写在浏览器的 IndexedDB 里，不会上传。换电脑时用页面里的 JSON 备份。

## 每天怎么用

1. **导入。** 打开页面，把当天的原始表拖进去。可以一次拖多份。支持 `.xls` 和 `.xlsx`。有的文件扩展名是 `.xlsx`，内容仍是旧的 Excel 97 格式，页面按文件内容识别，不看扩展名。
2. **核对日期。** 每份表的日期默认取文件创建时间，并换算成北京时间，可以手动改。同一天的奔强 `y099` 和 `Y100` 会合成一份 WIP。日期不对，两日对比就会错。
3. **看汇总。** 「导入」和「型号对比」顶部是汇总：
   - 奔强按型号（生产型号 + 客户料号）看自己最近最多三天，y099 和 Y100 分开。不使用固定工序顺序。工序名和上一天相同是无进度，不同是有变化。已出 WIP、今日新增仍按在不在来判断。页面和日报都列出这三天的工序。
   - 捷德仍按 60 道顺序号：更大是工序推进，相同是无进度，更小是工序回退，对不上顺序表是工序变化(顺序未知)。页面上的「三日状态」仍是原来的最远工序、数量签名、倒退、未动、风险。
4. **看五日进度。** 每个订单一行。奔强看工序名有没有变，捷德在工序旁边显示「第N/60道」。
   - **有变化**（奔强）：两天都在，工序名不同
   - **工序推进**（捷德）：两天都在，今日顺序号更大
   - **无进度**：奔强是工序名相同；捷德是最远顺序号相同。这一行会用底色标出
   - **工序回退**（捷德）：今日顺序号更小
   - **工序变化(顺序未知)**（捷德）：当天或上一天有工序不在顺序表里
   - **已出 WIP**：上一份有，这一份没有
   - **今日新增**：上一份没有，这一份有
   - **未在 WIP**：两份都没有匹配到
5. **看重点清单。** 「加急无进度」只留加急（「加急」或以「急」开头）并且无进度的订单。「交期预警」列出已逾期，或在设定天数内到期、且订单状态还不是「出库」的单。天数相对所选日期范围里最近一份 WIP 的日期。
6. **重点订单查询。** 输入一个编号就能看到进度、交期和数量。伯仁订单和「WIP 里有、伯仁订单里没有」的型号一起查。可以搜客户型号、生产编号、生产型号、厂编、投产单号、客户料号、客户PO、产品编号，包含匹配，不分大小写，全角半角和空格会先折掉。也可以只选其中一个字段。一次粘贴多个编号（换行、逗号、中文逗号、空格或制表符）时，没对上的编号会列出来。结果的「来源」是「订单+WIP」「仅订单」或「仅WIP」。已经对上 WIP 的订单只出现一次。仅 WIP 的结果显示 WIP 卡片，标明「仅WIP，伯仁订单无此单」。客户可以选捷德、奔强或全部，范围可以选加急、我关注的或全部订单。只找到一条时直接出卡片；找到多条时点一行展开。跟进备注和「我关注的」对订单和仅 WIP 都有效，按稳定编号存在这台电脑，并写进 JSON 备份。查询结果可以导出 Excel。日报的「重点订单」会带上被关注的仅 WIP 型号。
7. **筛选和导出。** 可以只看捷德或奔强，也可以限定日期范围，或按生产编号、厂编、客户型号搜索。「导出 Excel」在本机生成工作簿（不上传），含汇总统计、订单五日进度、加急且无进度、交期预警。汇总和这四张表跟随当前的供应商和日期范围。型号对比顶部的两日、三日数字仍按全部日期计算。用 WPS 2019 打开即可：只有数值，表头冻结，列宽按内容留出。
8. **生成日报 Excel。** 在「导入」页选择日期，点「生成日报 Excel」。会下载一份 `WIP日报_日期.xlsx`。捷德 310、奔强 y099、奔强 Y100 各自用自己最近一份有文件的日期当当天，再往前最多取两天做对比；某一来源当天没来文件，不会被当成已出 WIP。第 1/2/3 天列写的是真实日期和当天工序。奔强的进度是有变化或无进度，不写「第N/105道」。捷德的进度按顺序号，并写「第N/60道」。另外有一张「重点订单」，放加急单和「我关注的」，备注一起带上。原始 WIP 也是各来源的最新一份，表名里带日期。订单合成一张表。匹配会同时看生产编号、客户型号、生产型号、客户料号、厂编、产品编号、投产单号，先看多个字段一起对上，再退到单个字段；对上多条会标成一对多。没有客户料号的 Y100 仍用以前的型号回填料号。原来的四份分表收在「更多」里。用 WPS 2019 打开即可。
9. **工序顺序。** 只有捷德还用工序顺序。可以改顺序号、添加工序、删除、恢复默认，也可以导入两列 Excel（工序名称、顺序号）。改动存在这台电脑，并写进 JSON 备份。奔强这一页只说明不再使用。旧备份里如果还有奔强顺序，导入不会报错，也不会拿来比较。
10. **备份。** 换电脑前在「备份」下载 JSON，里面包含订单、WIP、「我关注的」、跟进备注和工序顺序。到新电脑打开同一页面，导入这个文件。不要把备份提交到这个公开仓库。

可以随时删掉某一份表，或清空本机数据。清空不影响已经下载的备份。

## 表怎么认

| 表 | 怎么认 | 日期 |
| --- | --- | --- |
| 奔强 WIP | 表头有生产型号、工艺名称即可。客户料号、客户PO、备注可以没有，列的顺序不限。标题、表名或型号前缀里有 Y100 的算 Y100，有 y099 的算 y099。某一天没有客户料号时，用以前各天「生产型号 → 客户料号」回填；还没有的，再用供应商厂编对生产型号 | 文件创建时间 |
| 捷德 WIP | 表头有投产单号、客户型号，以及至少一列工序名（开料、钻孔等）。销售合同数量、交期可以没有。工序列按表头名称认，不要求从固定列开始 | 文件创建时间 |
| 伯仁订单 | 表头有生产编号、供应商。外发交期、厂编、客户型号可以没有。供应商名称里有「奔强」或「捷德」 | 文件创建时间 |

奔强订单对 WIP，优先级是：

1. 生产编号 = WIP 客户料号，并且供应商厂编 = WIP 生产型号
2. 只对生产编号
3. 只对厂编

先看较新的一天，再看上一天。型号对比上的加急，是用 WIP 去找订单：先生产编号，找不到再厂编。

捷德订单对 WIP，用客户型号（去掉括号后面的说明）。同一型号有多张订单时，先按外发数量对销售合同数量；数量对不上就显示该型号的全部在制批次。工序数量为 0、`0` 或 `0.00` 视为空。

## 用 GitHub Pages 发布

这个仓库是纯静态文件，不需要构建。Pages 用「从分支部署」，目录选仓库根目录。根目录有 `.nojekyll`，避免 Jekyll 改写文件。

仓库主人在 GitHub 上这样设置：

1. 打开 <https://github.com/Link5268/wip-tracker>
2. 点上方的 **Settings**
3. 左侧点 **Pages**
4. 在 **Build and deployment** 里，**Source** 选择 **Deploy from a branch**
5. **Branch** 选择 **main**，右边的文件夹选择 **/ (root)**
6. 点 **Save**
7. 等页面上方出现 “Your site is live at https://link5268.github.io/wip-tracker/”。第一次大约要等一两分钟，然后打开这个地址。

如果 Source 里还没有 Deploy from a branch，先确认仓库是公开的，并且 `main` 分支上已经有 `index.html`。不要改成 GitHub Actions，除非以后页面改成需要构建。

## 本地打开

用任意静态文件服务器打开仓库根目录，例如：

```bash
python3 -m http.server 8765
```

然后访问 `http://127.0.0.1:8765/`。直接双击 `index.html` 时，浏览器可能拦截模块脚本，所以请用上面的方式打开。
